### P1.6 Dashboard range race condition
**File:** `src/client/components/Dashboard.tsx:48-55,123-153`

The current `abortRef` already aborts stale fetches, BUT the manual refresh (`doRefresh`) uses a separate `refreshAbortRef` and doesn't abort range fetches, and vice versa.

Fix: unify under a single generation token + abort all on range switch:

1. Add `genRef = useRef(0)` - increment on every range switch
2. In `fetchRange`: capture `const gen = ++genRef.current`, abort previous, check `gen === genRef.current` before `setPayload`
3. In `doRefresh`: capture `const gen = ++genRef.current`, abort previous (both range + refresh), check gen before `setPayload`
4. On range switch: abort both controllers, increment gen
5. **Alternative simpler approach:** Since `abortRef` already aborts stale range fetches and `ctrl.signal.aborted` is checked, the main gap is: `doRefresh` doesn't abort in-flight range fetches, and `fetchRange` doesn't abort in-flight refresh. Unify: both go through a single `abortRef`.

Actually re-reading the code: `fetchRange` line 71 aborts `abortRef.current` (previous range fetch), and `doRefresh` line 124 aborts `refreshAbortRef.current` (previous refresh). The race is: a range switch while a refresh is in-flight, or a refresh while a range fetch is in-flight. Fix: use a single shared `abortRef` for both, and check `ctrl.signal.aborted` after await (already done). Add gen check as belt-and-suspenders.

### P2.7 Dashboard "now" never advances
**File:** `src/client/components/Dashboard.tsx:46`

Replace `useMemo([payload])` with a ticking clock:
```tsx
const [now, setNow] = useState(() => payload ? new Date(payload.generatedAt) : new Date())
useEffect(() => {
  const id = setInterval(() => setNow(new Date()), 30_000)
  return () => clearInterval(id)
}, [])
// When payload changes, also update:
useEffect(() => {
  if (payload) setNow(new Date(payload.generatedAt))
}, [payload])
```
- 30s tick is enough for relative time granularity (seconds/minutes)
- On payload change, snap to server time to avoid drift
- **Note:** Also fixes the "in 1s" issue on fresh payload (now = generatedAt, so diff = 0, but `formatRelativeTime` should return "just now" for 0 diff - need to fix that too)

**Also fix `formatRelativeTime`:** when `secs < 60` and `!future`, return "just now" instead of "1s ago":
```ts

```
